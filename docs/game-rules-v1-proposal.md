# 모바일웹 첫 대전 규칙 제안 — 2026-10-16

상태: **직전 사용자에게 제시한 규칙 표 승인 완료**. 오픈/공격 택1, 수비자 피해 대상 선택, 가득 찬 전장의 비공개 버림, 교환 후 공격, 사망당 1장 보충, 엑조디아 우선 승패 판정, 특수 공격 게임당 1회·오픈 턴 공격 불가, 방어 칸 패시브, 재생 최대 3회, 게임 시작 스냅샷을 승인받았다. 아래 상세 제안 중 표에 없던 계정 운영 방식·효과별 적용 대상·세부 수치 처리 등은 새 설계 문서의 검토 대상이다. 과거 제안 표현은 근거 보존을 위해 남기며 현재 승인 범위는 이 문단을 기준으로 한다.

## 확정된 제품 범위

- Android 네이티브 개발 보류, 기존 React/Worker/D1 기반 모바일웹 우선.
- 정확히 2명, 한 기기에서 교대하는 가족 테스트. 온라인 실시간 매칭·별도 앱 패키징·AI 상담은 제외.
- 기존 로그인·승인 카드·진영 재사용. 최신 사용자 결정: 처음부터 서로 다른 두 실제 계정 사용. 한 로그인 계정 두 자리 제안은 폐기. 구체적인 한 기기 순차 로그인/대전 권한 흐름은 설계 문서 검토 대상.
- 승인·사용 가능 카드 20장 이상인 진영만 선택. 서로 다른 엑조디아 5장 + 비엑조디아 랜덤 15장, 총 20장.
- 서버가 덱 선정·셔플·전투·승패·세션 저장을 담당. 화면은 결과 표시와 행동 요청만 담당.

## 유지 권장하는 기존 규칙

- 각자 최초 1장 공개, 선공 랜덤·보정 없음. 엑조디아가 나오면 대기 칸으로 이동.
- 자기 턴은 오픈 또는 공격 중 택1. 수비자가 피해받을 공격/방어 카드를 선택. 행동 불가능한 경우만 자동 패스.
- 반격·공격자 HP 자동 소비·초과 피해 이월 없음. 엑조디아는 공개 대기 칸에만 존재하며 공격·사망 대상이 아님.
- 방어 칸 카드의 패시브만 활성화. 시간/턴 제한·자동 무승부는 추가하지 않음.

## 추가 추천안과 기존 답변의 충돌

1. **칸이 찬 상태의 오픈**: 엑조디아는 공개 대기 칸, 비엑조디아는 이름·이미지를 숨긴 버림 더미로 이동하고 턴 종료. 버림 카드는 복귀/전투 불가. 초기 답변의 사회자 확인을 모바일웹에서는 서버만 확인하는 것으로 해석하는 제안. 승패 판정에서는 버림 카드를 남은 전투 자원으로 세지 않음.
2. **방어 칸 카드의 공격**: 공격 행동에서 방어 카드를 공격자로 선택하면 먼저 공격 칸 카드와 자리를 교환하고 공격. 별도 추가 공격 없음. 단독 자리 교환 행동은 첫 버전에 넣지 않음. 패시브는 교환 후 방어 칸 기준. 이는 공격 칸만 공격 가능 규칙과 방어 카드도 공격 가능하다는 후속 답변을 결합하는 제안.
3. **사망 보충**: 죽은 칸마다 덱에서 정확히 1장만 무료 보충. 비엑조디아는 죽은 칸, 엑조디아는 대기 칸으로 가고 원래 칸은 빈 상태. 연속 무료 오픈이나 다음 턴 강제 스킵 없음. 일반 정규 오픈의 엑조디아 턴 종료와 구분. 보충 카드가 추가 공격권을 만들지는 않으며 다음 합법적인 자기 공격 기회에 사용 가능.
4. **동시 승패**: 사망 처리 → 무료 보충 → 엑조디아 5장 승리 확인 → 전장과 남은 덱 모두 전투 가능한 비엑조디아가 없으면 패배. 마지막 전투 카드가 죽어도 무료 보충에서 다섯 번째 엑조디아가 나오면 승리. 기존 감사 문서의 전투 패배 우선 제안과 다르지만 둘 다 미승인 제안이며, 원래 엑조디아 즉시 승리를 우선하는 안을 여기서 제시.
5. **특수 공격**: 카드 인스턴스당 게임 전체 1회. 이동/자리 교환으로 초기화되지 않음. 일반 공격 대신 쓰며, 정규 오픈한 턴에는 사용 불가. 초기 ‘오픈 직후 사용 가능’과 충돌하므로 변경 승인이 필요. 잘못된 대상은 실행 전에 UI에서 차단하고, 실제 실행된 실패 효과만 사용권 소비하는 방향은 별도 세부 설계 대상.
6. **효과와 계산**: 기본 공격력 → 공격 보정 → 방어 보정 → 소수점 버림 → 최소 피해 1 → HP 차감. 피해 효과에만 최소 1 적용. 방어 칸의 공격형 패시브는 아군 공격 칸 강화, 방어형은 효과 설명에 정한 대상만 보호, 회복형은 설명에 정한 대상/시점만 적용. 현재 임시 효과 목록을 그대로 전투 규칙으로 확정하지 않고 효과별 대상·조건·횟수를 별도 설계.
7. **무한 회복 방지**: 재생 패시브는 해당 카드가 방어 칸에서 자기 턴을 시작할 때 최대 HP의 5% 회복, 게임당 카드별 최대 3회로 제한하는 안. 실제 HP가 회복될 때만 횟수를 소비하고 자리 이동으로 초기화하지 않음. 카드별 1회인 회복 특수 공격은 유지. 기존 재생 효과에 횟수 제한을 추가하는 변경이므로 사용자 승인 전 구현하지 않음. 승인/활성 카드의 출전 풀과 20장 조건을 임의 변경하지 않음. 턴 제한·자동 무승부는 추가하지 않으며 자발적인 반복 행동까지 유한 종료를 보장하지는 않음.
8. **수치 밸런스**: 기존 HP/공격력 허용 범위는 유지. 최초 테스트 세트를 맞춰 제작하고 전투 로그로 비교. 검증되지 않은 등급별 점수 예산이나 승률을 강제로 도입하지 않음.
9. **게임 중 카드 수정**: 시작 시 카드 버전·수치·효과·덱 순서를 고정 저장. 이후 어드민 수정/사용 중지/보관은 다음 대전부터 반영. 화면 새로고침으로 재추첨하거나 특수 공격 횟수가 초기화되지 않음.

## 구현 전 남은 설계

- 두 실제 계정의 인증과 게임 참가자 ID를 연결. 한 기기에서 두 인증을 확인한 뒤 교대하는 흐름은 설계 문서에서 정리. 계정 확인과 실제 기기 교대자의 신원 확인은 구분하며 온라인 부정행위 방지를 완성했다고 설명하지 않음.
- 처음 공개한 카드의 배치 선택, 빈 칸이 두 개인 정규 오픈 배치, 초기 엑조디아 처리 후 첫 행동 가능 여부.
- 피해 대상 선택 요청의 대기 상태와 재접속, 중복 행동 방지, 게임 데이터 API의 비공개 덱 필터.
- 효과 6종의 정확한 대상/시점/반올림/제한과 첫 버전 지원 목록.
- 서버 세션·행동 API·모바일 UI·검증 시나리오는 규칙 승인 후 설계 문서에서 정리.
